One query at a time, FAISS has to stream the whole 512 MB dataset from RAM for every query. That is consistent with being limited by memory bandwidth, at roughly 20 GB/s on one core. In a batch, distances are computed as a matrix–matrix product over blocks of vectors that stay in cache while every query uses them, so each vector is read from RAM once per batch. That makes the batch about 3.5–3.8× faster on one thread. The batch can also be split across cores for another 2.3–2.6×, while a single query is not split across threads.

I didn't measure memory bandwidth or cache misses directly. I did confirm that forcing FAISS's matrix-product path accounts for the single-thread gain. In this FAISS build, small batches such as 200 queries don't use that path and run at the one-at-a-time speed.
