One query at a time, FAISS has to stream the whole dataset (512 MB for SIFT, 473 MB for GloVe) from RAM for every query, so it is limited by memory bandwidth: 25.8 ms and 23.1 ms per query, i.e. about 20 GB/s on one core. In a batch, distances are computed as a matrix–matrix product over blocks of vectors that stay in cache while all the queries use them, so each vector is read from RAM once per batch instead of once per query. This makes the batch 3.5× (SIFT) and 3.8× (GloVe) faster on a single thread. The batch can also be split across the 10 cores for a further 2.6× and 2.3×, whereas a single query is barely helped by extra threads.

Caveats: the memory-bandwidth explanation is inferred from the timings; bandwidth and cache misses were not measured directly. Forcing FAISS onto its matrix-product path gave the same single-thread speed-up on SIFT, which supports the explanation, and in this FAISS build (1.15.1) a 200-query batch did not use that path and ran no faster than one query at a time, so the gain depends on the batch size.
